# S1 세 구간과 한 발 보행

브랜치: `codex/wave-gait-three-zone`

## 조작

SC가 조종 모드일 때 CH10(S1)을 보정된 전체 입력 범위로 나눈다. 정확한 33.3%, 66.6% 경계는 가운데에 포함한다.

| S1 위치 | 내부 값 | 보행 | Throttle | Yaw 짐벌 |
|---|---:|---|---|---|
| 33.3% 미만 | 0 | 기존 Tripod, 세 발씩 | 전진·후진 | 좌우 회전 |
| 33.3~66.6% | 2 | Wave, 한 발씩 | 전진·후진 | 좌우 회전 |
| 66.6% 초과 | 1 | 기존 Tripod, 세 발씩 | 전진·후진 | 좌우 평행이동 |

현재 CH10 보정값 `191~1792`, 방향 `+1`에서는 raw `725~1257`이 가운데 구간이다. 중앙 보정값의 비대칭과 채널 반전도 처리한다. 오른쪽 모드의 Heading 자동 오차 보정은 기존 설정 `ROBOT_GAIT_YAW_FEEDBACK_ENABLE=0`을 유지한다.

## 논문 적용

사용자가 제공한 「오프로드 환경에서 효율적인 6족 로봇의 보행」 4.2절, 본문 55~58쪽(PDF 69~72쪽), 그림 4.2.1~4.2.3을 참고했다. 논문의 오른쪽 중간 다리부터 시계 방향으로 매긴 번호에 따른 `6 → 3 → 1 → 5 → 2 → 4`를 이 저장소의 물리적 다리 배치로 변환했다.

| 순서 | 저장소 다리 번호 | 위치 |
|---:|---:|---|
| 1 | 1 | 오른쪽 앞 |
| 2 | 6 | 왼쪽 뒤 |
| 3 | 2 | 오른쪽 중간 |
| 4 | 4 | 왼쪽 앞 |
| 5 | 3 | 오른쪽 뒤 |
| 6 | 5 | 왼쪽 중간 |

정상 보행에서 한 번에 한 발만 Swing하고 다섯 발은 지지한다. 매 이동발의 접촉 확정과 여섯 발 접촉을 확인한 뒤 다음 발의 경로를 검사한다. 논문의 다리 순서와 개별 접촉 원리를 현재 Bézier·FSR·IK 구조에 적용한 것이며 논문의 모든 하드웨어·제어 알고리즘을 재현한 것은 아니다.

## 동작과 조정값

- 한 발의 기본 Swing 시간은 기존과 같은 `1.0 s`, 한 순회는 접촉 대기를 제외하고 약 `6 s`다.
- 다섯 지지 위상 동안 발의 보폭이 누적되는 점을 반영해 `ROBOT_WAVE_SPEED_SCALE=0.2`를 적용한다. 감속 후 전후 요청 상한은 `±0.02 m/s`, 회전은 `±3.6 deg/s`다. 경로 검사에서 추가 축소할 수 있다.
- Swing 끝점은 다섯 지지 위상의 이동량을 사용한다. 지지발은 매 위상마다 위치를 재설정하지 않고 실제 발 위치부터 몸체 이동 반대 방향으로 연속 이동한다.
- 최초 여섯 위상은 지지발 이동량을 절반으로 줄여 아직 들어 올리지 않은 발이 중립 위치에서 과도하게 뒤로 밀리지 않게 한다.
- Wave는 한 발 착지마다 새 입력을 검사한다. 짐벌을 놓으면 현재 발의 착지를 마치고 정지한다. Tripod의 기존 두 걸음 명령 유지·정지 방식은 유지한다.
- Tripod ↔ Wave 전환은 현재 Swing이 끝나고 여섯 발 접촉이 확인된 뒤 적용한다. 새 패턴은 입력 안정 대기와 경로 검사를 다시 거친다.
- Early Landing, 접촉 후보 고정, Late Landing, 지지발 재접촉 대기와 탐색 한계 정지를 유지한다. Late Landing 중 정상 지지발 이동을 계속 누적하지 않는다.
- 기존 공통 Z 복구는 세 발의 동시 착지 오차를 묶는 Tripod 전용 방식이므로 Wave에서는 해제한다. 개별 접촉 위치 고정과 지면 탐색은 유지한다.
- 이 작업본의 `main.c`는 `SENSOR_RAW_TEST_MODE=0`으로 일반 보행 앱을 실행하도록 설정했다. 기존 센서 측정 코드 변경분은 보존했다.

## 검증

GNU Tools for STM32 `14.3.rel1`로 84개 소스의 Cortex-M4 전체 컴파일·링크를 검사했으며 오류·경고는 없었다. 일반 보행 실행 설정의 ELF 크기는 text `119280 B`, data `468 B`, bss `15072 B`다. 실제 보드 업로드와 실물 보행 시험은 실행하지 않았다.

ARM 명령 에뮬레이션에서 다음 검사를 통과했다.

- S1 두 경계의 포함 여부, 양 끝 제한, 비대칭 보정과 채널 방향 반전
- 세 구간의 우선순위 전달, 회전·평행이동 분기, 전후진과 양방향 회전 입력
- 두 순회 이상의 한 발 순서와 다섯 지지발 상태
- 공중에서 정지, 양방향 패턴 전환, 새 경로 승인 대기, 시작 접촉 누락
- 전진+회전 시 지지점 연속성과 착지 지연 중 지지점 유지
- 실제 접촉 모형 → 경로 검사 → 발 궤적 → IK를 연결한 전진·후진·회전 순회
- Wave의 매 발 입력 갱신과 실제 지지점이 작업공간 밖일 때 경로 거부
- 기존 사용자 입력, 작업공간, 상위 제어, Tripod 명령 유지와 지지발 복구 회귀 검사

기존 `GaitTest_CheckLateLandingLimit`과 `ModeTransitionTest_Run`의 실패가 수정 전 `main` (`a60055e`)에서도 동일하게 재현됐다. 전자는 종합 `GaitTest_Run`도 실패시키므로 전체 회귀 묶음을 전부 통과한 상태는 아니다. 이번 변경에서 해당 기존 실패를 감추거나 시험을 제외하지 않았다.

실물에서는 로봇을 지지한 상태에서 S1 세 구간과 발 순서를 먼저 확인한 뒤 낮은 짐벌 입력으로 접촉·정지·전환을 확인한다. 빌드와 알고리즘 검사는 실제 FSR 보정, 모터 하중, 미끄러짐과 무게중심 안정성을 검증하지 않는다.
